Postly (tesis n8n, autores Hassan + Bontorno, UTN FRM 2026). La doc `docs/Tesis Postly Bontorno Hassan.docx` es la **fuente de la verdad** y no se puede deviar de lo documentado (decisión del usuario, 2026-06-25).

**Brecha doc vs. realidad:** la tesis define el **Módulo A (Seguridad, Onboarding, Autenticación)** como fundacional y como punto #1 del MVP, con flujo **OAuth 2.0 Authorization Code Grant** (HU2): token largo de 60 días obtenido y guardado cifrado en Google Sheets **sin hardcodear**. La realidad hoy: tokens cortos de Meta **hardcodeados a mano** en los nodos httpRequest (IG - Crear contenedor / IG - Publicar / Permalink).

**Bloqueante raíz:** el túnel `trycloudflare` efímero cambia de URL en cada reinicio, lo que rompe el Callback/Redirect URI de Meta (HU2), el redirect URI de Google Cloud Console (re-auth de Sheets) y el webhook de Telegram. **Sin URL estable no se puede implementar HU2.**

**Camino acordado (doc-faithful):** la tesis (Sprint 1) documenta **VPS + Docker + proxy inverso + SSL/TLS** y declara el self-hosting como NFR "innegociable". El destino final es VPS (skill `n8n-self-hosting`), pero Oracle Cloud rechazó las tarjetas virtuales (MercadoPago/Lemon) y el usuario no quiso usar la de un familiar **por ahora**. Oracle queda pendiente.
